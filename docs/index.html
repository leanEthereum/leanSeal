leanSeal

Time-lock encryption from hashes alone. Seal a transaction so that anyone can open it after a fixed amount of sequential hashing, or at once when its sender reveals the key.

Why

In an encrypted mempool, block builders order transactions before they can read them. The hard part is opening them afterwards. A committee holding a decryption key asks you to trust that no threshold of its members colludes. Letting the sender reveal its own key lets the sender walk away from an ordering it dislikes. Efficient time-lock puzzles avoid both, but rely on RSA or class groups, which need a trusted setup or fall to quantum computers.

leanSeal uses nothing but SHA-256. Behind commit–reveal, users reveal their keys as usual and nothing is ever solved; a user who stays silent cannot cancel a transaction with a well-formed puzzle, because anyone can force it open.

How it works

  1. The sender draws n random links and runs n hash chains of m SHA-256 steps, all in parallel, one per link.
  2. The puzzle publishes the first link in the clear and hides each later link under a hash of the end of the chain before it. The key is a hash of every chain's end.
  3. An opener without the key learns each link only by finishing the previous chain, so it must run all n·m steps one after another, however much hardware it has.

What we show

A proved delay

In the random-oracle model, a classical attacker derives the key even one oracle round early with probability about 2−116 for a one-minute lock, against the hash rate of the whole Bitcoin network.

An affordable sender

The sender's work is unavoidable for hash-only time locks, but it can be paid in advance: a wallet can keep a stock of puzzles and build more while idle or charging.

A clear limit

Delay encryption, where one computation per slot opens every transaction sent to it, is impossible from hashes alone when the setup is cheap. Per-transaction puzzles are what hashes can do.

A specified implementation

A versioned byte format with test vectors, a Rust implementation with SHA-256 hardware backends, and an independent Python implementation that agrees on every vector.

Status

leanSeal is a research proof of concept. The proof of the delay theorem has not been machine-checked or reviewed by a third party, and no human cryptographer has reviewed the code. Post-quantum security is proved for the idealized chained puzzle; a bound for leanSeal's exact encoding against quantum attackers is open. Do not protect anything valuable with it yet.

Try it

git clone https://github.com/leanEthereum/leanSeal && cd leanSeal
make && make test
target/release/leanseal gen -n 16 -m 2^30 -o tx.secret     # build a puzzle
target/release/leanseal encrypt -s tx.secret -i tx.bin -o tx.env
target/release/leanseal open tx.env --solve -o tx.bin      # anyone, after n·m steps
